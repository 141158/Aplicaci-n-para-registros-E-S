1. Resumen Ejecutivo

El presente informe detalla la arquitectura, diseño e implementación de una aplicación cliente-servidor orientada a la visualización y análisis pedagógico de las operaciones de Entrada y Salida (E/S) dentro del Sistema Operativo Windows. La herramienta permite capturar en tiempo real las interacciones de los periféricos (teclado, ratón) e instanciar operaciones de disco (HDD/NVMe) para demostrar el tránsito de la información a través de las capas del sistema, incluyendo conceptos avanzados como Interrupciones (IRQ), Paquetes de Petición de I/O (IRP), la Capa de Abstracción de Hardware (HAL) y el Acceso Directo a Memoria (DMA).

2. Arquitectura Tecnológica

La aplicación utiliza un modelo asíncrono cliente-servidor basado totalmente en WebSockets para garantizar tiempos de respuesta en milisegundos y un bajo consumo de recursos:

Python 3 (Asyncio) WebSockets Vanilla JavaScript (ES6) HTML5 / CSS3 WMI (Windows Management Instrumentation) Pynput

2.1 El Servidor (Backend)

Construido en Python (`backend_os.py`), actúa como un puente de bajo nivel interactuando con las APIs de Windows. Sus funciones primordiales son:

  • Detección Dinámica de Hardware (WMI): Accede a la interfaz WMI nativa de Microsoft (`Win32_AllocatedResource` y `MSFT_PhysicalDisk`) para descubrir los controladores, líneas IRQ, modelo de unidades físicas, y detectar correctamente el protocolo de bus usado por el almacenamiento (clasificando automáticamente NVMe vs SATA).
  • Hooking Espacial de Entradas: Utiliza la librería pynput para interceptar eventos de teclado y ratón antes de que lleguen a la aplicación enfocada por el SO, permitiendo reportar su estado al momento preciso.
  • Inyector de E/S Aislada: Implementa una función especializada para generar una carga real de 50MB que elude el caché del sistema de archivos mediante os.fsync, demostrando la interacción directa con el medio físico.

2.2 El Cliente (Frontend)

Construido usando tecnologías web estándar (`index.html`, `app.js`, `styles.css`), presenta una interfaz inmersiva estilo "Glassmorphism" con un pipeline visual de datos. Renderiza múltiples flujos de log paralelos sin saturar el DOM y gestiona la latencia y la sincronización de mensajes para mantener el aspecto de consola.

3. Características Clave y Demostración Teórica

3.1 Visibilidad de IRQ y Controladores

El sistema extrae dinámicamente qué "Línea de Petición de Interrupción" (IRQ) están utilizando los dispositivos críticos. Esto documenta cómo la arquitectura de la PC moderna maneja las señales asíncronas de los dispositivos hacia la CPU utilizando el controlador APIC.

3.2 Cámara Avanzada de Captura de Disco (I/O)

Se diseñó una funcionalidad avanzada que demuestra cómo ocurre una solicitud I/O moderna a nivel del Kernel NT. Una vez se selecciona el disco (NVMe o HDD) y se fuerza un I/O de 50MB, la aplicación inicia su seguimiento:

  • User Space API: Evidenciando llamadas al subsistema nativo (`NtWriteFile` / `NtReadFile`).
  • Creación de IRP: Demuestra cómo el I/O Manager del Kernel crea un Paquete de Petición de I/O (`IRP_MJ_WRITE`/`READ`) para enviarlo por la pila del controlador.
  • Interacción HAL / DMA: Se visualiza la delegación de la transferencia mediante DMA (Direct Memory Access). En este paso, la CPU configura a los controladores (`stornvme.sys` o `storahci.sys`) para que muevan los datos a la memoria RAM de manera autónoma. La aplicación mide la tasa empírica de transferencia (MB/s).
  • Completación de Interrupción: El emulador muestra el alzamiento de la IRQ y la posterior Rutina de Servicio de Interrupción (ISR) y DPC requeridas para notificar al subproceso de usuario que los datos han llegado.
El gran valor didáctico reside en contrastar la latencia y velocidades logradas por el Controlador de un SSD NVMe conectado directamente al bus PCIe, frente un HDD tradicional atado al ecosistema SATA/IDE.

4. Conclusión

El desarrollo de esta herramienta permite una interiorización tangible y visual de conceptos abstractos propios del diseño de los sistemas operativos. El proyecto demuestra que combinando Python para acceso al API del sistema base y tecnologías web modernas para la reactividad de la interfaz, se puede conseguir un entorno educativo versátil que no depende de compilaciones en espacio de kernel, y reduce las fricciones en el aprendizaje de Arquitectura de Computadoras.
